# Sub2API 0.1.155 升级与账号管理增强设计

## 背景与目标

当前生产环境运行自定义镜像 `0.1.153-image-routing.5`，程序版本低于官方
`0.1.155`，因此后台持续提示存在新版本。本次升级需要在保留图片主路由、渠道监控、
账号健康检查等自定义能力的同时同步官方主线，并完成以下账号管理增强：

1. 图片转接模型可在后台动态配置。
2. JSON 导入账号时可同时绑定多个分组。
3. 账号统计中可查看该账号的导入 JSON，敏感字段受控展示。
4. 修复 OpenAI 账号关闭训练数据共享失败的问题。

## 集成与版本策略

以现有 `feat/chatgpt2api-image-routing` 为集成分支，将官方 `upstream/main`
合并进来并解决冲突。应用内 `VERSION` 保持官方版本 `0.1.155`，从而让官方更新检查
继续按上游版本工作；自定义版本只体现在容器镜像标签
`0.1.155-custom.1`，不污染应用版本比较。

不得只修改版本文件而跳过官方代码合并。发布时由 GitHub Actions 构建 amd64 镜像，
Azure 服务器只负责拉取镜像、执行数据库迁移、健康检查和滚动替换。

## 图片转接模型设置

在“系统设置 -> 网关”增加“图片转接模型”下拉框，仅允许：

- `codex-gpt-image-2`：界面显示“Codex 图片通道”，默认值。
- `gpt-image-2`：界面显示“GPT Image 图片通道”。

设置键为 `chatgpt2api_image_model`。运行时读取优先级为：数据库设置、环境变量
`CHATGPT2API_IMAGE_MODEL`、默认值 `codex-gpt-image-2`。后台保存后立即生效，
无需重启容器。后端使用白名单验证，非法值返回 HTTP 400。

模型能力与账号套餐解耦，不根据 Free、Plus 或其他账号类型隐藏或拒绝
`codex-gpt-image-2`。实际可用性由上游请求结果决定。

## 多分组账号导入

导入弹窗将单选默认分组改为多选，提交字段为：

```json
{
  "default_group_ids": [1, 2, 3]
}
```

后端继续接受旧字段 `default_group_id`。当新旧字段同时出现时，以
`default_group_ids` 为准；数组去重并忽略重复项。后端验证分组存在、状态为启用且平台
兼容，任何无效分组都使本次请求返回明确的 HTTP 400，不执行部分分组绑定。

每个成功新建的账号绑定全部选中分组。账号导入本身已有的部分成功语义保持不变：
单个账号数据错误不回滚其他合法账号，但结果必须逐项报告成功或失败原因。

## 导入 JSON 快照与安全展示

### 存储

为账号保存独立的导入快照，包含原始导入对象、导入时间和导入批次标识。快照使用
项目现有凭据加密能力加密后落库，不把原始 JSON 放入账号 `extra`，也不写入普通
应用日志。非 JSON 导入创建的账号没有快照，界面显示“无导入记录”。

同一账号后续再次导入并更新时，以最新一次成功导入快照覆盖旧快照，同时更新导入
时间和批次标识。

### 接口

普通账号列表、详情和统计接口均不得返回完整快照。账号统计接口仅返回：

- 是否存在导入快照。
- 导入时间和批次标识。
- 递归脱敏后的 JSON。

敏感键按大小写归一化匹配，包括 token、secret、password、cookie、authorization、
session、key 等。字符串仅保留少量首尾字符；嵌套对象和数组递归处理。

查看完整 JSON 使用单独的管理员接口。前端先显示二次确认框，确认后临时请求完整
内容；关闭弹窗即清除前端内存中的完整数据，不写入 localStorage 或 sessionStorage。

每次完整查看写入审计记录，至少包含管理员 ID、目标账号 ID、动作、时间和请求来源
IP。审计日志不得包含快照正文。接口响应禁止被浏览器和代理缓存。

## OpenAI 隐私设置修复

当前隐私请求只携带 Bearer Token 和基础浏览器头，生产日志显示上游返回 403 HTML。
项目内可正常访问 ChatGPT 后端的配额接口还会携带 `chatgpt-account-id`、
`openai-beta`、`originator`、`oai-language` 等账号上下文头。隐私请求应复用同一套
账号解析和公共请求头构造逻辑，而不是维护另一套不完整请求。

执行流程：

1. 加载账号并解析影子账号对应的真实凭据账号。
2. 通过 TokenProvider 获取可用 access token。
3. 从 credentials 的 `chatgpt_account_id` 读取账号 ID，缺失时回退
   `organization_id`；仍缺失则返回可操作的“请重新授权”错误。
4. 使用账号绑定代理和统一 ChatGPT 请求头调用隐私设置接口。
5. 成功后写入 `privacy_mode=training_off`；失败则保存结构化失败分类。

失败分类包括：Token 无效、缺少账号 ID、Cloudflare 挑战、上游拒绝、网络或超时。
Cloudflare 判断使用 HTML 标题、challenge 脚本等稳定特征，不再仅凭宽泛的 `cf-`
字符串判断。

管理员手动设置接口在失败时返回对应的 4xx/502 状态和错误码，不再外层返回 200、
仅在 `extra` 中留下失败状态。自动刷新令牌过程仍采用 best-effort，不因隐私设置失败
阻断令牌刷新。

## 前端交互

- 导入弹窗使用现有分组多选控件，显示已选数量，可搜索并清空选择。
- 账号统计/详情弹窗增加“导入信息”区，默认显示格式化的脱敏 JSON。
- “查看完整内容”属于高风险操作，使用警告样式和二次确认；完整内容展示期间提供
  明确的“隐藏”操作。
- 隐私设置成功后立即刷新该账号状态；失败时显示具体原因，不把所有 403 都描述为
  IP 或 Cloudflare 问题。
- 图片模型设置沿用网关设置区域的表单、保存和校验交互，不新增独立页面。

## 测试策略

实现遵循测试优先：每项行为先增加失败测试，再编写最小实现。

后端测试覆盖：

- 官方版本比较不把自定义镜像标签作为应用版本。
- 图片模型默认值、数据库覆盖、环境变量回退和非法值。
- 新旧分组字段兼容、去重、无效分组拒绝和多分组绑定。
- 快照加密保存、递归脱敏、完整查看权限、禁止缓存和审计写入。
- 隐私请求包含账号上下文头，影子账号解析和各类失败映射。

前端测试覆盖：

- 多分组选择和请求载荷。
- 脱敏快照默认展示、二次确认、完整内容隐藏和内存清理。
- 图片模型选项、默认值和保存请求。
- 隐私设置失败原因展示及成功后刷新。

合并官方代码后运行后端相关单测、完整 Go 测试、前端单测、类型检查和生产构建。
部署后验证版本接口、后台版本徽标、设置读写、测试账号多分组导入、快照脱敏接口及
隐私设置真实请求。真实完整凭据不得出现在测试输出或部署日志中。

## 发布与回滚

1. 推送集成分支到 `1832094726/sub2api`。
2. GitHub Actions 构建并推送 `ghcr.io/1832094726/sub2api:0.1.155-custom.1`。
3. Azure 备份数据库与当前 Compose 配置，拉取新镜像并运行迁移。
4. 新容器健康后切换服务；验证失败则恢复旧镜像
   `0.1.153-image-routing.5` 和对应数据库快照。

数据库迁移必须向前兼容旧容器读取账号基础数据；新增快照表和设置项不能改变现有
账号字段语义。
